## 결론

첫 리팩터링 단위는 시험 데이터의 쓰기 대상 제한입니다. 관리자 키로 시드·정리를 실행하기 전에 허용된 로컬 주소인지 검사합니다. 기존 작업은 별도 워크트리로 보존합니다. 이 문서는 사업안 전체 승인이나 운영 배포 승인이 아닙니다.

## 판단 근거

- 작업 ID: W02. 기준 커밋: `b3760d4b8d6cda03767ab5ffdbb991d7074a17cd`. 위험등급 L3.
- `e2e/global-setup.ts`는 일반 `.env.local`을 덮어 읽고 시드를 실행합니다. `e2e/helpers/seed.ts`와 두 slice 시험도 직접 관리자 클라이언트를 만듭니다.
- `scripts/seed-dummy-data.ts`의 cleanup은 여러 테이블에서 전체 행을 삭제합니다. 이메일 접미사는 DB 격리 수단이 아닙니다.
- 근본 원인: 시험용 관리자 쓰기 경로에 대상 DB 계약이 없고, 환경 로드와 클라이언트 생성이 중복되어 있습니다.

## 고정할 계약

`config/test-database.json`을 이 작업의 주소 허용 목록으로 둡니다. 최초 목록은 `http://127.0.0.1:54321`, `http://localhost:54321`뿐입니다. 환경변수만으로 외부 주소를 허용할 수 없습니다. 목록 변경은 코드 리뷰 대상입니다.

- 입력: 명시적으로 주입한 `NEXT_PUBLIC_SUPABASE_URL` 또는 `SUPABASE_URL`, `SUPABASE_SERVICE_ROLE_KEY`. 두 URL을 함께 지정하면 같은 origin이어야 합니다. E2E 전체 실행은 앱과 동일한 `NEXT_PUBLIC_SUPABASE_URL` 및 `NEXT_PUBLIC_SUPABASE_ANON_KEY`도 필요합니다.
- 일반 `.env.local` 자동 로드를 시드와 E2E 관리자 도구에서 제거합니다. URL·키를 명시적으로 주입해야 합니다. Next 자체 환경 로더는 수정하지 않습니다.
- 성공 출력: `{ url: string, serviceRoleKey: string }`. URL은 허용 origin으로 정규화합니다. 마지막 `/` 하나만 허용합니다.
- 오류: `Error`, 메시지는 `[TEST_DB_TARGET]`으로 시작하며 URL 원문·키를 포함하지 않습니다. 잘못된 URL, 자격증명·경로·query·fragment 포함, 미허용 origin, URL 별칭 충돌, 필수 키 누락이면 실패합니다.
- 검사는 spawn·Supabase 클라이언트 생성·DB 요청보다 먼저 실행합니다. `SKIP_DEMO_SEED=1`도 대상·필수 키 검증을 생략하지 못합니다.
- 이 제한은 설정 오류로 외부 DB에 쓰는 경로를 줄입니다. 로컬 포트가 운영 DB에 프록시되지 않았다는 보증이나 실제 격리 DB 검증은 아닙니다.
- DB 스키마·RLS·제품 API·승인 UI 카피·수수료·보상은 변경하지 않습니다. 관리자용 다른 수동 스크립트 전체를 보호한다고 주장하지 않습니다.

| AC03 | When 허용 URL과 명시적 키를 받으면 시스템은 기존 seed/cleanup 호출을 유지해야 합니다. | 모든 실행을 막는 킬 스위치 |
| AC04 | While seed 생략 옵션이 켜져 있어도 시스템은 E2E 대상 검증을 수행해야 합니다. | 생략·누락을 성공으로 보고 |
