# B2B Recruiter Intelligence PRD

> 작성일: 2026-05-01  
> 상태: Phase 2 선행 MVP  
> 상위 원천: `docs/prd-6.0.md`, `CLAUDE.md`  
> 구현 진입점: `/admin/b2b`, `/api/admin/b2b/analyze`

## 1. 문제 정의

기업 리크루터는 자사 JD, 데스크탑/GDrive에 흩어진 후보자 이력서, 시장의 채용 공고를 각각 따로 본다. 이 과정에서 다음 문제가 생긴다.

- 자사 JD와 후보자 이력서의 적합도를 일관된 기준으로 비교하기 어렵다.
- 시장에서 같은 도메인·직무가 어떻게 요구되는지 확인하려면 별도 리서치가 필요하다.
- 후보자가 자사 JD에는 맞아 보이지만 시장 기준으로 상위권 인재인지 판단하기 어렵다.
- 이력서가 구조적으로 잘 작성됐는지, AI가 만든 일반론에 가까운지 구분하기 어렵다.

## 2. 제품 목표

B2B Recruiter Intelligence는 리크루터가 입력한 자사 JD와 후보자 이력서를 VCX의 채용 시그널 데이터와 대조해, “이 후보자를 왜 검토해야 하는가”를 1차 큐레이션 리포트로 만든다.

MVP 목표:

- JD와 이력서 텍스트를 붙여넣거나 출처 URI로 추적한다.
- 출처는 `manual`, `desktop`, `gdrive`를 지원한다.
- Supabase/SQLite에 저장된 시장 채용정보를 도메인 섹터와 직무 연관성 기준으로 리스팅한다.
- 후보자의 JD 적합도, 시장 기준 상위권 추정, 이력서 구조 점수, AI 작성 가능성 점수를 제공한다.

## 3. 사용자

| 사용자 | 니즈 |
|---|---|
| VCX 운영자 | 기업 JD와 후보자 이력서를 빠르게 선별하고 추천 근거를 남긴다. |
| 기업 리크루터 | 자사 JD 기준 적합 후보와 시장 비교군을 보고 싶다. |
| 기업 리더 | 면접 전 후보자가 왜 추천됐는지 짧고 신뢰 가능한 근거를 원한다. |

## 4. 핵심 플로우

1. 리크루터가 자사 JD를 입력한다.
2. JD 출처를 선택한다: 수동 입력, 데스크탑 파일, Google Drive 문서.
3. 후보자 이력서 원문과 메타데이터를 입력한다.
4. 시스템은 저장된 `positions`, `vcx_feed_items`, `vcx_b2b_market_job_signals`를 가져온다.
5. 도메인 섹터, 직무명, 스킬, 본문 키워드 기준으로 시장 채용정보를 랭킹한다.
6. JD와 이력서 매칭 점수 및 사유를 만든다.
7. 이력서의 시장 가치, 구조 품질, AI 작성 가능성을 별도 점수로 제공한다.
8. 필요 시 JD, 이력서, 분석 결과를 B2B 테이블에 저장한다.

## 5. 기능 요구사항

### 5.1 JD·이력서 입력

- JD 필수 필드: 회사명, 직무명, 도메인 섹터, JD 본문.
- JD 선택 필드: 시니어리티, 필수 스킬, 우대 스킬, 출처 URI.
- 이력서 필수 필드: 이력서 본문.
- 이력서 선택 필드: 후보자명, 현재 직함, 경력 연차, 경험 도메인, 보유 스킬, 출처 URI.
- Google Drive 연동은 MVP에서 파일 권한/OAuth까지 직접 처리하지 않고 `source_type='gdrive'`, `source_uri`로 추적한다.

### 5.2 시장 채용정보 리스팅

- 데이터 원천:
  - `vcx_b2b_market_job_signals`
  - `positions`
  - `vcx_feed_items`
- 정렬 기준:
  - 도메인 섹터 일치
  - 직무명 키워드 일치
  - 필수/우대 스킬 태그 일치
  - JD 본문과 시장 채용정보 본문 키워드 겹침
- 출력:
  - 회사명, 직무명, 출처, 섹터, 연관성 점수, 연관 근거.

### 5.3 JD-이력서 매칭

- 점수 범위: 0~100.
- 판정 라벨: 강한 추천, 검토 추천, 보류, 낮은 적합도.
- 산출 근거:
  - 핵심 스킬 일치
  - 직무명 관련성
  - 도메인 섹터 관련성
  - 시니어리티/경력 신호
  - JD 본문과 이력서 본문 키워드 겹침
- 리스크:
  - 필수 스킬 부족
  - 도메인 경험 불명확
  - 직무명 연결성 약함
  - 원문 길이 부족

### 5.4 시장 가치·이력서 품질·AI 작성 가능성

- 시장 가치 추정:
  - 경력 연차
  - 보유 스킬 수
  - 시장 채용정보의 요구 스킬과의 겹침
  - 성과/리더십 신호
- 구조 품질:
  - 경력, 성과, 프로젝트, 학력, 스킬 등 섹션 존재
  - 숫자 성과 포함 여부
  - 원문 길이와 정보량
- AI 작성 가능성:
  - 일반적인 수식어 과다
  - 구체적 숫자 부족
  - 반복적인 bullet 패턴
  - 긴 일반론 문장 비중
- 주의: AI 작성 가능성은 확정 판별이 아니라 휴리스틱 기반 신호다.

## 6. 데이터 모델

신규 마이그레이션: `supabase/migrations/024_vcx_b2b_intelligence.sql`

| 테이블 | 목적 |
|---|---|
| `vcx_company_jds` | 기업 JD 원문, 스킬, 출처를 저장 |
| `vcx_candidate_resumes` | 후보자 이력서 원문, 스킬, 출처, 동의 상태를 저장 |
| `vcx_b2b_market_job_signals` | 외부/내부 시장 채용정보 시그널을 저장 |
| `vcx_b2b_match_runs` | 분석 결과 스냅샷을 저장 |

보조 개발 환경:

- `sqlite/schema.sql`
- `sqlite/seed.sql`
- `npm run sqlite:smoke`

## 7. 보안·프라이버시

- 후보자 이력서는 관리자만 CRUD 가능하다.
- 기업 사용자는 자기 JD 조회/생성만 가능하며, 후보자 이력서 원문은 직접 볼 수 없다.
- 커뮤니티 라운지 데이터는 이 기능에 사용하지 않는다.
- `source_uri`는 파일 식별자 추적용이며, 공개 URL 저장을 전제로 하지 않는다.
- 후보자 외부 공유 전에는 별도 동의 상태가 필요하다.

## 8. MVP 수용 기준

- `/admin/b2b`에서 샘플 JD와 이력서로 분석을 실행할 수 있다.
- `/api/admin/b2b/analyze`는 관리자만 접근할 수 있다.
- 분석 응답에는 `match`, `assessment`, `market_jobs`가 포함된다.
- 저장 옵션을 켜면 신규 B2B 테이블에 원문과 분석 결과가 저장된다.
- SQLite smoke가 B2B seed 데이터를 검증한다.
